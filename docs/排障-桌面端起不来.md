# 复盘：DSH 桌面端起不来、会话「消失」、任何会话都输入不了

> 时间：2026-10-31 上午
> 环境：DSH 桌面端 0.2.1-rc.2（Electron 44.7.0 / Node 24.21.0），profile = `desktop`
> 结果：靠网页端 `dsh web` 进来救回，桌面端恢复可用；**一条会话都没丢**。

---

## 一、三个现象，其实是两件事

### 图三：会话不见了

会话列表是空的，看着像全丢。

**其实没丢。** 那是「筛选会话」筛选条件的问题——列表默认停在 **隐藏已归档**，
一旦有会话被归档过，看起来就像一片空白。

**怎么确认**：`侧栏 → 工作区 → 筛选会话`，切到 **「全部对话（显示已归档）」**，会话全回来了。

> 这条要记住：**先怀疑视图，再怀疑数据。** 会话文件躺在 `~/.dsh/sessions/` 里，
> 一个被归档的会话不会因为看不到就被删掉。

### 图一 / 图二：桌面端起不来

- **图一**（在还能进的那条路里看到的）：
  ```
  resume failed for session "session-…": Error: no agent factory registered
  (load an agent-loop plugin) (gateway/internal)
  ```
  意思：**agent-loop 这个插件没激活**，于是没有「agent 工厂」，任何会话都开不了、也输不进去。

- **图二**（桌面端启动时的致命错误框）：
  ```
  The application could not start or stopped unexpectedly.
  … cordis-host-runner / cordis-inspect-providers / bili-scroll / memory /
  qq-bridge / nekowhale-stickers / cover-pipeline / dsh-read-animation  tools
  ```
  意思：`1 required plugin did not activate`，另外 14 个插件在**等 `tools` 这个服务**。

**这两个是同一件事的两面**：`tools` 服务没起来 → `agent-loop`（required）起不来 →
渲染端拿不到 agent 工厂（图一），宿主端统一报致命错（图二）。

### 报错是怎么产生的

看 `%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-2026-10-31T06-47-51-348Z-host.log`：

```
DesktopHostFatalError: dsh: startup failed: 1 required plugin did not activate

Plugins waiting for services (14):
  Plugin                     Missing services
  agent-loop (required)      tools
  tool-working-directory     tools
  …
```

链条很清楚：

1. 往 profile 的 `dsh.profile.bundles` 里塞了一个第三方插件（这次是 `dsh-computer-use`，npm 上的 0.3.1）；
2. 它跟当前内核版本不匹配，**启动装配时抛错**，提供 `tools` 服务的那一环没起来；
3. `tools` 没了 → 依赖它的 14 个插件全部「等待服务」→ `agent-loop` 是 required，直接把启动判死；
4. 桌面端 = 白屏 / 弹「could not start」，**重试没用**（每次都走到同一个带毒配置）。

> 关键认知：DSH 的插件**只在启动时装配一次**。所以「改完重启页面」没用，必须整个退出再开；
> 而带毒的 bundle 会让你连启动都过不去——**这时不要跟桌面端较劲，换一条能跑的入口进去修**。

## 二、修复步骤（实际做的，按顺序）

### 0. 先别慌，先确认数据

- 会话在 `~/.dsh/sessions/**/session.v4.jsonl.zstd`，**插件崩不会动它**；
- profile 配置在 `~/.dsh/profiles/desktop/package.json`；
- 崩溃日志在 `%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-*.log`（**这一步一定要看**，它直接告诉你谁在等谁）。

### 1. 用另一条路进来 —— 网页端 `dsh web`

桌面端起不来时，用同一台机器上自建的 Node 环境跑 `dsh web`，
它读的是**同一个 profile、同一份会话数据**，完全权限下能把桌面端修回来。
（这里不展开怎么搭环境；记住结论就行：**能跑起来的那个入口，就是你的手术台**。）

### 2. 定位到具体插件

按日志里「who is waiting for what」对一遍：
`agent-loop` 等 `tools`，`tools` 没人提供 → 问题不在这些插件身上，而在**让 `tools` 死掉的那个新插件**。
对应到这次：`dsh-computer-use`。

### 3. 备份，再回滚

```powershell
$p = "$env:USERPROFILE\.dsh\profiles\desktop\package.json"
Copy-Item $p "$p.bak-$(Get-Date -Format yyyyMMdd-HHmm)"   # 先备份当前（有毒的）状态
Copy-Item "$p.bak-computer" $p -Force                      # 再用干净的备份覆盖
```

> 备份意识：**每次改 `package.json` 之前先复制一份**。
> 这次能几分钟修好，靠的就是之前留的 `.bak-computer`。

### 4. 把插件从两个地方都摘掉

一个插件要「生效」，得同时出现在两处：

- `dependencies`（`"dsh-computer-use": "^0.3.1"`）
- `dsh.profile.bundles`（数组里那一行）

**只删一个不够**，剩下的那半会让启动继续失败。

### 5. 重装依赖

```powershell
cd "$env:USERPROFILE\.dsh\profiles\desktop"
$env:CI = "false"
pnpm install
```

- `CI=false`：不然 pnpm 会走 frozen-lockfile 模式，锁文件和 `package.json` 不一致时报错停下；
- 正常结果会看到「removed N packages」（这次是 -41），说明多余的东西清掉了。

### 6. 彻底退出桌面端，再打开

不是刷新、不是最小化：**结束进程 / 从托盘退出**，确认没有残留，再启动。
插件清单只在启动装配一次。

### 7. 验证

- 能进主界面、不弹错误框；
- 会话列表有内容（记得看「全部对话」）；
- 随便一间会话能正常输入、能收到回复；
- 插件页面里各个插件都是「已激活」。

## 三、存档留档（这次事后补的，建议照做）

| 存什么 | 在哪 | 为什么要 |
|---|---|---|
| profile 的 `package.json` | 每次改动前 `Copy-Item … .bak-<日期>-<原因>` | 出事能 30 秒回滚 |
| 崩溃日志 | `%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-*.log` | 「谁在等谁」只有它说得清 |
| 会话原始文件 | `~/.dsh/sessions/**`（别手改） | 这是记忆本体，插件崩不影响它 |
| 恢复后的可用配置 | 另存一份 `package.json.good-<日期>` | 下次再崩，有「已知能跑」的参照 |
| 一次简短的复盘（就是本文） | 你的档案目录 / 仓库 docs | 下次自己或别人遇到，直接照做 |

一句话原则：**配置可回滚、日志要留、会话别动。**

---

## 四、给别人的三条提醒

1. **别急着把新插件塞进 bundles。** 先在干净 profile 里单装、单启，确认能开再加别的。
2. **「会话没了」先看筛选，再看磁盘。** 归档 ≠ 删除。
3. **桌面端起不来 ≠ 数据没了。** 换 `dsh web` 进来，读同一个 profile，把带毒的配置摘掉就能救回来。
